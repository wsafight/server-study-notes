---
title: DuckDB 扩展与安全边界
description: 管理 DuckDB 扩展来源、版本、自动加载、文件系统和网络访问能力。
---

DuckDB 扩展可以增加文件格式、对象存储、数据库连接和空间分析能力。扩展通常包含与进程同权限运行的原生代码，因此安装和加载属于软件供应链行为，不只是执行一条普通 SQL。

## 区分安装与加载

```sql
INSTALL httpfs;
LOAD httpfs;
```

`INSTALL` 获取与当前 DuckDB 平台和版本匹配的扩展文件，`LOAD` 将它载入当前进程。部分已知函数可能触发自动安装或自动加载，便于交互使用，但生产环境应明确控制这种网络和代码执行行为。

离线或受限环境中，应在构建阶段预装所需扩展，将 DuckDB 版本、平台和扩展清单作为一个发布单元测试。升级核心版本后重新获取匹配扩展，不要复制未知兼容性的旧二进制。

## 固定可信来源

只允许官方仓库或经过组织审核的扩展来源，并验证传输、安全签名和制品完整性。不要为了加载内部测试二进制在生产长期启用允许未签名扩展的配置。

记录：

- DuckDB 核心版本和客户端包版本。
- 扩展名称、来源、版本或构建标识。
- 目标操作系统和 CPU 架构。
- 安装时间、校验结果和审批来源。

依赖自动下载时，还要考虑仓库不可用、代理、证书轮换和制品被撤回后的恢复方案。

## 限制运行能力

能够执行任意 DuckDB SQL 的主体可能读取本地文件、访问远程 URL、安装扩展或写出结果。运行用户提供的 SQL 时，应在进程和操作系统层隔离：

- 使用专用低权限系统用户和临时工作目录。
- 只挂载允许读取的输入和允许写入的输出目录。
- 限制出站网络、云元数据地址和内部控制面。
- 不把长期云凭据或数据库密码放入进程环境。
- 设置 CPU、内存、临时磁盘和执行时间上限。

DuckDB 配置中有关扩展自动加载、外部访问和文件系统的开关会随版本演进。应使用锁定版本验证实际效果，并把拒绝测试纳入 CI。

## Secret 生命周期

Secret 可以为对象存储和外部数据库提供凭据。优先使用工作负载身份和短期令牌，限制 Scope 到具体服务或路径。明确 Secret 是仅内存存在还是持久化，以及持久化目录权限。

日志、Profiling、异常栈和查询历史可能包含连接字符串。使用不含密码的命名 Secret 引用，并在采集前脱敏。

## 数据文件也是输入边界

Parquet、CSV、JSON 和压缩文件来自不可信来源时，同样应视为解析器输入。限制文件数量、单文件大小、解压后大小、嵌套深度和单行长度，在隔离环境先验证 Schema。

升级 DuckDB 或扩展时，使用恶意与异常样本做回归测试，并运行依赖安全审计。文件读取成功不表示数据可信，仍需执行业务级约束和质量检查。

## 发布检查

在无外网环境启动任务，确认所需扩展都能加载；尝试加载未批准扩展、读取越界文件和访问未授权地址，确认操作被拒绝且日志不泄密。最后验证镜像回滚时旧版本仍能读取已发布数据格式。
