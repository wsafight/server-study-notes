---
title: 使用 vmstat 分析内存与系统队列
description: 解读 vmstat 的进程、内存、换页、I/O 和 CPU 指标。
---

`vmstat` 是 Virtual Memory Statistics 的缩写，可以同时观察运行队列、内存、换页、块 I/O、系统调用和 CPU 状态。

```bash
vmstat 1 5
```

`1 5` 表示每秒采样一次，共输出五次。第一行通常是自系统启动以来的平均值，分析当前问题时重点看后续区间数据。

## 关键指标

| 分类 | 指标 | 含义 |
| --- | --- | --- |
| 进程 | `r` | 正在运行或等待 CPU 的任务数 |
| 进程 | `b` | 处于不可中断睡眠的任务数 |
| 内存 | `free` | 当前完全空闲的内存 |
| 内存 | `buff`、`cache` | 缓冲区和页缓存占用 |
| 换页 | `si`、`so` | 每秒从 swap 换入和换出的数据量 |
| I/O | `bi`、`bo` | 每秒从块设备读入和写出的块数 |
| 系统 | `in`、`cs` | 每秒中断和上下文切换次数 |
| CPU | `us`、`sy` | 用户态和内核态 CPU 时间比例 |
| CPU | `id`、`wa`、`st` | 空闲、I/O 等待和虚拟机 steal 时间 |

## 判断思路

- `r` 长期明显高于可用 CPU 数，说明 CPU 运行队列存在竞争。
- `b`、`wa` 与磁盘延迟同时升高时，继续使用 `iostat` 和 `pidstat -d` 定位 I/O。
- `si`、`so` 持续非零通常表示内存压力和活跃换页；仅看到 swap 已占用并不能证明当前正在换页。
- `free` 很低不一定是问题，Linux 会使用空闲内存作为缓存，应结合 `available`、换页和应用延迟判断。
- `cs` 异常升高可能来自线程竞争、频繁唤醒或大量短任务，需要结合进程级上下文切换继续分析。

`vmstat` 适合快速建立整体判断，但无法直接指出具体进程，应与 `pidstat`、`free` 和应用监控一起使用。
