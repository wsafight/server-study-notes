---
title: 排查 Linux 磁盘 I/O
description: 从容量、文件系统、设备队列和进程 I/O 定位磁盘延迟、空间耗尽与吞吐瓶颈。
---

磁盘故障既可能表现为 I/O 延迟，也可能是空间、inode、只读挂载或设备错误。排查时先确认逻辑路径最终落在哪个块设备、卷、云盘或网络存储上。

## 检查容量和挂载

```bash
df -hT
df -ih
findmnt
lsblk -o NAME,TYPE,SIZE,FSTYPE,MOUNTPOINTS
```

`df` 与应用看到的空间不一致时，检查是否存在已删除但仍被进程打开的大文件：

```bash
lsof +L1
```

也要确认预留空间、配额、容器临时盘和云盘突发额度。inode 耗尽时，即使仍有字节空间也无法创建新文件。

## 观察设备延迟

```bash
iostat -xz 1 10
cat /proc/pressure/io
```

需要结合观察：

- `r/s`、`w/s` 与 `rkB/s`、`wkB/s`：操作次数和吞吐。
- `await`：请求从进入设备队列到完成的平均时间。
- `aqu-sz`：平均排队与执行中的请求数。
- `%util`：设备处理 I/O 的时间比例。
- PSI：任务因 I/O 停顿的时间。

不能用统一阈值判断所有设备。并行能力强的 NVMe、阵列和虚拟设备即使 `%util` 较高也可能仍有余量；合并请求、缓存和云盘实现也会影响统计。应把延迟与业务 SLO、设备基线和队列深度一起看。

## 找到产生 I/O 的进程

```bash
pidstat -d 1 10
cat /proc/<pid>/io
```

数据库写入可能先进入页缓存，之后由内核回写线程集中落盘，因此瞬时设备写入不一定完全归到原业务进程。结合应用指标、脏页、WAL/redo、文件系统和备份任务的时间线判断。

## 检查错误与抖动

```bash
journalctl -k --since "-2h"
dmesg -T
```

关注 I/O error、timeout、reset、只读重新挂载和文件系统告警。`dmesg` 读取权限可能受限，且环形缓冲区会覆盖旧消息，应使用集中日志保留历史证据。

常见抖动来源包括大批量日志、数据库 checkpoint、快照、备份、磁盘扩容、邻居租户争用和云盘突发额度耗尽。

## 修复方向

- 限制批任务并发与每批数据量，让写入速率保持可持续。
- 将日志、临时文件和数据库数据放在符合故障域与性能要求的存储上。
- 优化访问模式、索引和缓存之前，先证明瓶颈来自 I/O 工作量。
- 扩盘同时处理文件系统、卷管理和告警阈值，不能只修改云盘规格。
- 发生设备错误时优先保护数据与冗余，不要用反复重试掩盖硬件故障。

更详细的指标解释参见[使用 iostat 分析磁盘 I/O](../sysstat-iostat/)。
