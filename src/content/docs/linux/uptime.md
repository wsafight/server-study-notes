---
title: 使用 uptime 理解平均负载
description: 正确解读 Linux 的 1、5、15 分钟平均负载，并区分 CPU 与 I/O 压力。
---

`uptime` 可以快速查看系统运行时间、登录用户数和平均负载趋势。

```bash
uptime
```

示例输出：

```text
08:16:48 up 5 min, 1 user, load average: 0.34, 0.49, 0.27
```

- `08:16:48` 是当前时间。
- `up 5 min` 是系统持续运行时间。
- `1 user` 是当前登录会话数。
- 最后三个数字分别是过去 1、5、15 分钟的平均负载。

## 平均负载是什么

Linux 平均负载统计处于可运行状态（正在使用 CPU 或等待 CPU）以及不可中断睡眠状态的任务数量。不可中断睡眠常见于等待 I/O，但不只限于磁盘。

平均负载需要结合逻辑 CPU 数解释：

```bash
nproc
```

在一个 8 CPU 系统上，持续负载约为 8 表示平均有 8 个活跃任务，但不代表一定存在性能故障。负载为 12 表示平均还有约 4 个任务正在等待 CPU 或处于不可中断状态。容器中还应考虑 CPU quota 和 cpuset，而不能只看宿主机 CPU 数。

## 如何判断趋势

- 1 分钟值高于 5 和 15 分钟值，负载可能正在上升。
- 1 分钟值低于较长周期值，负载可能正在恢复。
- 没有适用于所有系统的固定告警百分比，应根据业务延迟、吞吐、错误率和历史基线设定阈值。

平均负载高不等于 CPU 使用率高。CPU 密集任务会同时推高负载和 CPU 使用率；大量不可中断 I/O 等待也会推高负载，但 CPU 可能仍有空闲。

继续诊断时可以按顺序执行：

```bash
mpstat -P ALL 1
vmstat 1
pidstat -u -r -d -w 1
iostat -xz 1
```

`uptime` 用于发现趋势，具体瓶颈仍需通过进程和资源指标确认。
