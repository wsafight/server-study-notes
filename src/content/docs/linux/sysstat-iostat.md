title: 使用 iostat 分析磁盘 I/O
description: 通过吞吐、等待时间、队列和设备利用率判断磁盘是否成为瓶颈。
---

`iostat` 来自 `sysstat` 软件包，用于观察块设备吞吐、请求延迟、队列和 CPU 的 I/O 等待情况。

## 安装与采样

```bash
sudo apt install sysstat
iostat -xz -y 1 5
```

- `-x` 显示扩展设备指标。
- `-z` 隐藏采样周期内没有活动的设备。
- `-y` 忽略自系统启动以来的第一组累计数据。
- `1 5` 表示每秒采样一次，共输出五次。

## 关键指标

不同 `sysstat` 版本的列名可能略有差异。

| 指标 | 含义 |
| --- | --- |
| `r/s`、`w/s` | 每秒读写请求数 |
| `rkB/s`、`wkB/s` | 每秒读写吞吐量 |
| `await` | 请求从进入队列到完成的平均时间 |
| `aqu-sz` | 平均请求队列长度 |
| `%util` | 设备处理 I/O 的时间比例 |

## 判断思路

- `await` 持续升高且队列增长，通常说明请求超过设备当前处理能力。
- 高吞吐但低延迟可能只是设备被充分利用，不一定需要优化。
- `%util` 接近 100% 对传统单队列磁盘较有参考价值；对 NVMe、RAID 和云盘等并行设备，不能单独用它判断饱和。
- CPU 的 `%iowait` 较高只说明 CPU 有空闲时间且存在未完成 I/O，仍需结合设备指标定位。

最后把异常设备映射到挂载点、文件系统和具体进程，再使用 `pidstat -d` 或应用监控继续缩小范围。
