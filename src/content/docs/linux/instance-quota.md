---
title: 估算服务实例数量
description: 根据峰值流量、单实例安全容量、发布策略和故障域计算实例配额。
---

实例数量不能只用平均 QPS 相除。计算时至少要同时考虑峰值流量、单实例安全容量、发布期间不可用实例数，以及单个故障域可能损失的容量。

## 基础容量

假设压测确认单实例在满足延迟和错误率 SLO 时，可以稳定处理 `100 QPS`，预计峰值为 `3470 QPS`：

```text
基础实例数 = ceil(3470 / 100) = 35
```

这里的 `100 QPS` 应是保留了 CPU、内存、连接池和下游波动余量后的安全容量，而不是短时极限值。

## 加入冗余

可以使用下面的思路估算最低实例数：

```text
最低实例数 = 基础实例数
           + 发布期间最大不可用实例数
           + 最大单一故障域损失的实例数
```

如果滚动发布最多下线 1 个实例，且任意一台主机故障只会损失 1 个实例，则至少需要 `35 + 1 + 1 = 37` 个实例。如果同一主机或可用区承载多个实例，故障冗余必须按实际损失数量增加，不能固定套用 `N + 2`。

## 上线前验证

- 使用接近生产的数据量、请求比例和依赖延迟进行压测。
- 同时观察 P95/P99 延迟、错误率、CPU、内存、GC、线程池和连接池。
- 验证一台主机或一个可用区故障时，剩余实例仍能满足 SLO。
- 确认自动扩缩容的触发指标、冷启动时间、最小副本数和最大扩容速度。
- 为突发流量保留余量，并对下游数据库、缓存和消息系统做同样的容量检查。

容量模型需要结合真实监控持续校准。业务模式、代码版本或依赖变化后，应重新压测而不是沿用旧的单实例 QPS。
